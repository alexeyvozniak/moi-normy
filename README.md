# Правило

**Версия 1.0.2** · август 2026  
**Автор: Алексей Возняк**

Личное локальное PWA для молитвы, чтения, медитации и других регулярных практик. Приложение работает без сервера, поддерживает офлайн-режим и хранит пользовательские данные на устройстве.

## Версия 1.0

В первую готовую версию входят:

- дневные, недельные, месячные и интервальные нормы;
- отдельный режим молитвенной практики со счётом по сотням;
- книжный режим с расчётом объёма чтения до срока;
- медитация с двумя этапами и заметкой;
- история выполненных действий и возврат значения при удалении записи;
- экран «Неделя» с просмотром ритма по дням;
- раздел «Путь» для книг, заметок, завершённых практик и изменений правила;
- локальные напоминания, звуки практики, экспорт и импорт данных;
- офлайн-работа через service worker и локальная резервная копия в IndexedDB.

## Архитектура

Приложение остаётся статическим PWA без сервера. Пользовательские данные не находятся в репозитории: основное состояние хранится локально в `localStorage` под ключом `pravilo_v1`, а модуль офлайн-хранения делает локальную резервную копию в IndexedDB. В `pravilo_v1` входят занятия, история, напоминания и остальные данные приложения; старый ключ `pravilo_reminders_v1` используется только для одноразовой автоматической миграции старых напоминаний.

Основные файлы:

- `index.html` — статическая оболочка интерфейса без номера сборки и бизнес-логики.
- `app-manifest.js` — единственный источник версии приложения, порядка CSS/JS-модулей и списка обязательных offline-ассетов.
- `app.css` — базовая тема и базовые компоненты.
- `designer-fonts.css` — локально доступная типографика без сетевой зависимости.
- `responsive.css` — общая адаптация основного интерфейса под размеры экранов; специализированные полноэкранные режимы имеют собственные локальные media queries.
- `ui-controls.css` — общие интерактивные элементы: кнопки, переключатель паузы, кнопка настроек.
- `ui-dialog.css` + `ui-dialog.js` — единый диалог подтверждения для опасных действий.
- `feature-ui.css` — интерфейс режима книги, заметок, справки и обновлений.
- `mode-tools.css` — интерфейс режимов счётчика и экспорта заметок.
- `app-core.js` — единственный основной источник состояния, базовый рендеринг, CRUD занятий, история и импорт/экспорт.
- `accrual.js` — календарное начисление обычных норм.
- `book-mode.js` — единственная реализация режима книги и расчёта дневного объёма до срока.
- `counter-mode.js` — накопительный режим и «с чистого дня».
- `practice-types.js` — назначение специального режима занятию.
- `prayer-practice.js` — полноэкранный счётчик молитвы.
- `meditation-practice.js` — таймер медитации, тема до/после практики и заметка.
- `audio.js` — единый аудиослой: короткие молитвенные сигналы запускаются через HTMLAudio из пользовательского касания, отложенный колокол медитации — через разблокированный WebAudio.
- `path.js` — раздел «Путь», журнал книг, практик и изменений правила.
- `notes.js` — заметки чтения и медитации.
- `notes-export.js` — экспорт заметок в Markdown.
- `history-delete.js` — удаление отдельных событий из истории.
- `offline-storage.js` — локальная резервная копия в IndexedDB; слушает событие сохранения ядра и не подменяет `save()`.
- `reminders.js` — локальные напоминания внутри общего состояния `pravilo_v1`; при первом запуске переносит данные из старого отдельного ключа, если они есть.
- `settings-hub.js` — детерминированная иерархия настроек; звук, данные и приложение открываются отдельными вложенными экранами.
- `app-help.js` — инструкция и проверка обновления по центральному manifest.
- `app-self-test.js` — без изменения данных проверяет manifest, загрузчик и наличие ключевых модулей/элементов после старта.
- `app-bootstrap.js` — загружает модули в порядке из `app-manifest.js`, умеет самостоятельно восстановить manifest при старой оболочке и фиксирует ошибки загрузки.
- `sw.js` — строит offline-cache из того же `app-manifest.js`; HTML/JS/CSS получают свежую сетевую версию при наличии сети и откатываются на локальную копию офлайн.
- `.github/workflows/validate.yml` — проверяет синтаксис JavaScript, доменную логику, manifest, наличие всех перечисленных ассетов и границу единственного источника версии при каждом push.

### Правило разработки

1. Пользовательское состояние живёт только в `pravilo_v1`; модуль не создаёт параллельную копию состояния для своей бизнес-логики.
2. Модуль не переписывает функции `app-core.js`; взаимодействие идёт через состояние и события `pravilo:state-saved`, `pravilo:editor-open`, `pravilo:editor-saved`, `pravilo:render`.
3. Одна функция приложения имеет одну реализацию. Старый модуль удаляется после переноса, а не остаётся «на всякий случай».
4. Номер версии, список модулей и offline-ассетов меняются только в `app-manifest.js`.
5. Service worker кэширует приложение, но не меняет его разметку и бизнес-логику. Для кода и стилей используется network-first с офлайн-fallback.
6. Общая адаптивная вёрстка не дублируется между файлами; локальные media queries допускаются только для самостоятельных полноэкранных компонентов.
7. Изменение не считается законченным, пока `Validate Pravilo` не проходит синтаксис, доменные тесты и проверку manifest/локальных ссылок.

## Изображения

Основные иллюстрации лежат в `images/`. Среди них образы молитвы, чтения, медитации, статистики, иллюстрации «Недели» и «Истории», а также изображения приветственного экрана и иконки разделов настроек.

Обои лежат отдельно в корне репозитория и не участвуют в работе приложения.
