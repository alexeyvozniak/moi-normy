# Правило

Личный PWA-трекер молитвы, чтения, медитации и других регулярных норм.

## Архитектура

Приложение остаётся статическим PWA без сервера. Пользовательские данные не находятся в репозитории: основное состояние хранится локально в `localStorage` под ключом `pravilo_v1`, а модуль офлайн-хранения делает локальную резервную копию в IndexedDB.

Основные файлы:

- `index.html` — только статическая оболочка интерфейса; бизнес-логики внутри нет.
- `app.css` — базовая тема и базовые компоненты.
- `designer-fonts.css` — локально доступная типографика без сетевой зависимости.
- `responsive.css` — адаптация карточек под размеры экранов.
- `ui-controls.css` — общие интерактивные элементы: кнопки, переключатель паузы, кнопка настроек.
- `ui-dialog.css` + `ui-dialog.js` — единый диалог подтверждения для опасных действий.
- `feature-ui.css` — интерфейс режима книги, заметок, справки и обновлений.
- `mode-tools.css` — интерфейс режимов счётчика и экспорта заметок.
- `app-core.js` — единственный основной источник состояния, базовый рендеринг, CRUD занятий, история и импорт/экспорт.
- `accrual.js` — календарное начисление обычных норм.
- `book-mode.js` — единственная реализация режима книги и расчёта дневного объёма до срока.
- `counter-mode.js` — накопительный режим и «с чистого дня».
- `practice-types.js` — назначение специального режима занятию.
- `prayer-practice.js` — полноэкранный счётчик молитвы.
- `meditation-practice.js` — таймер медитации, тема до/после практики и заметка.
- `path.js` — раздел «Путь», журнал книг, практик и изменений правила.
- `notes.js` — заметки чтения и медитации.
- `notes-export.js` — экспорт заметок в Markdown.
- `history-delete.js` — удаление отдельных тестовых событий из истории.
- `offline-storage.js` — локальная резервная копия в IndexedDB; слушает событие сохранения ядра и не подменяет `save()`.
- `reminders.js` — локальные напоминания.
- `settings-hub.js` — структура настроек.
- `app-help.js` — инструкция и проверка обновления.
- `app-self-test.js` — без изменения данных проверяет наличие ключевых модулей и элементов после загрузки.
- `app-bootstrap.js` — явный порядок подключения независимых модулей.
- `sw.js` — только офлайн-кэш и жизненный цикл PWA; не переписывает HTML и не внедряет скрипты.
- `.github/workflows/validate.yml` — проверяет синтаксис JavaScript, локальные зависимости и отсутствие старых дублирующих модулей при каждом push.

### Правило разработки

1. Пользовательское состояние живёт только в `pravilo_v1`; модуль не создаёт параллельную копию состояния для своей бизнес-логики.
2. Модуль не переписывает функции `app-core.js`; взаимодействие идёт через состояние и события `pravilo:state-saved`, `pravilo:editor-open`, `pravilo:editor-saved`, `pravilo:render`.
3. Одна функция приложения имеет одну реализацию. Старый модуль удаляется после переноса, а не остаётся «на всякий случай».
4. Service worker кэширует приложение, но не меняет его разметку и логику.
5. Изменение не считается законченным, пока `Validate Pravilo` не проходит синтаксис и проверку локальных ссылок.

## Изображения

Основные иллюстрации лежат в `images/`. Среди них образы молитвы, чтения, медитации, статистики, три японские иконки разделов настроек (`settings-reminders.webp`, `settings-data.webp`, `settings-app.webp`) и отдельная японская шестерёнка `settings-gear.webp` для кнопки перехода в настройки.

Обои лежат отдельно в корне репозитория и не участвуют в работе приложения.
